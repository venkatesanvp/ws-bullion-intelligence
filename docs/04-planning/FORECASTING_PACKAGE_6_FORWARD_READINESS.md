## Proposed minimum compliant design - not implemented

1. Qualify source rights, timestamp/session/finality/action/revision semantics and maintained trading calendar. Assign reviewed policy versions with actual review times.
2. During an explicitly authorized owner-triggered forecast, issue an immutable event at actual time: instrument/ISIN/exchange/currency, source/basis/vintage and policy references, model/version/configuration, origin/cutoff/target, original availability stamps, input IDs/hashes and result ID. Retain exact values or source input evidence only when permitted. Hash-only records help identity/integrity but cannot by themselves reproduce or independently validate a restricted price calculation.
3. Assess outcomes separately after finality/availability: record actual outcome availability, source revision/vintage, target-path completeness, signed/absolute/normalized errors and evaluation status. Never overwrite issuance or rewrite a prediction to fit later prices; append correction/revision events and block comparisons when basis/inputs become incompatible.
4. If persistent retention is authorized, review a minimal append-only issuance/outcome ledger and allowed encrypted backups with integrity/restore tests, bounded retention, deletion and permissions. Choose the existing PostgreSQL architecture rather than introducing deployment infrastructure. Model/performance records must retain mode/dataset/window/qualification/configuration so replay and forward results cannot be pooled accidentally.
5. Require chronology/audit/replay and restart-recovery verification, qualified prospective support and a predeclared statistical protocol before live predictive-reliability claims. Keep conditional replay as a separate descriptive mode. Automated collection/scheduling, external ML/Kronos and trading require separate reviewed scope.

No ledger/schema/migration, storage permission, new feed/scheduled job or acquisition infrastructure was introduced in Package6. Current transient registries are functional session research; losing them on restart is an explicit limitation, not forward-validation acceptance.
