## Four critical scanner findings in PostgreSQL image

All four identify Go stdlib 1.24.6 embedded in `/usr/local/bin/gosu`; direct inspection confirms gosu 1.19 built for linux/amd64 with Go 1.24.6. These are not findings in our Python calculations or evidence of a remotely exploitable PostgreSQL SQL endpoint.

| ID | Scanner score / fix | Qualification in this configuration | Remaining action |
|---|---|---|---|
| CVE-2026-56857 | 9.8; Go 1.26.9 per scanner | **Not applicable to this Linux binary:** official Go advisory describes Windows junction/root-directory operations. Raw scanner finding remains recorded. | Retain explicit platform disposition; do not silently suppress. |
| CVE-2026-78663 | 9.1; Go 1.26.9 | HTTP/2 flow-control issue. Reviewed gosu main is local user switching/exec, not an HTTP server. Binary-level reachability has not been qualified. | OPEN: verify compiled-symbol reachability and/or select patched compatible image/helper. |
| CVE-2026-39821 | 9.6; Go 1.25.13 | IDNA/HTTP host processing issue. No such request-processing path appears in reviewed gosu main; transitive/binary reachability not proven. | OPEN: qualify reachability and/or use patched compatible toolchain. |
| CVE-2025-68121 | 10.0; Go 1.24.13 | TLS session-resumption/configuration-mutation issue. Gosu is a startup exec helper, not a persistent TLS service; binary reachability not independently verified. | OPEN: qualify reachability and/or use patched compatible image/helper. |

Primary evidence: [gosu 1.19 source](https://github.com/tianon/gosu/blob/1.19/main.go), [gosu lifecycle](https://github.com/tianon/gosu/blob/1.19/README.md), official Go [Windows advisory](https://pkg.go.dev/vuln/GO-2026-6604), [HTTP/2 advisory](https://pkg.go.dev/vuln/GO-2026-6612), [IDNA advisory](https://pkg.go.dev/vuln/GO-2026-5026), [TLS advisory](https://pkg.go.dev/vuln/GO-2026-4337).

Source review suggests reduced reachability for the three network-related findings, but is not a completed binary call-graph assessment or permission to waive them. The PostgreSQL image's original digest remains unchanged to avoid an unassessed database/locale/volume compatibility change. Critical-image qualification remains a release gate.

## Other unresolved exposures and remediation implications

- API uv/uvx contains quinn-proto 0.11.15 and quick-xml 0.39.2 advisories. They are indirect toolchain content, not installed project venv dependencies. uv is used for startup/frozen commands; remote package/metadata processing is the relevant potential exposure. Replace with an officially verified patched pinned uv image/binary after frozen-lock, CLI and startup compatibility checks; do not strip the supported uv command just to reduce counts.
- Debian apt, zlib and other libc/util-linux/Perl/OS findings are inherited production-image content. UI is read-only/non-root; database is internal/authenticated; API is loopback/authenticated. These controls reduce exposure but do not establish non-exploitability. apt is not invoked by normal application routes. Native compression/runtime-library reachability needs advisory-specific assessment.
- Scanner lists some fixes (for example apt 3.0.4 / 2.6.2); others report `not fixed` for the approved stable distro. Use tested, digest-pinned compatible image updates or reviewed backports. Do not replace Debian/PG major, run unpinned blanket upgrades, reset volumes or waive vulnerabilities without review. [Debian zlib tracker](https://security-tracker.debian.org/tracker/source-package/zlib) independently retains stable-release issues.
- Earlier setuptools/urllib3/msgpack findings were located in inherited pip vendor metadata, outside the application venv. That unused runtime tooling was removed and rescanned, rather than suppressing findings. [Setuptools upstream advisory](https://github.com/pypa/setuptools/security/advisories/GHSA-5rjg-fvgr-3xxf) supplies the affected function/fix; application exposure should never be inferred from a package name alone.

## Proposed material security decision

Before release clearance, authorize a bounded base-image/toolchain hardening and reachability increment: verify the gosu binary advisories; select patched same-major PostgreSQL/Python/Node/uv digests where compatible; assess locale/data-layout/entrypoint changes; repeat isolated backup/restore and startup, full regression, credential checks and all image scans. No active-volume replacement/reset, new deployment infrastructure, external market-data request or breaking distro/PG-major change is part of this proposal. This is not acceptance of the remaining risk.
