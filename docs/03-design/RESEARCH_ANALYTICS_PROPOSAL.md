# Research analytical/data contracts - proposal for review

Date 2026-11-06. Packages 2-6 only; **not implemented or approved mathematical changes**. Existing ADR-01/02/06/07 and canonical Decimal OHLCV remain unchanged. Parent: [twelve-part assessment](../04-planning/RESEARCH_EXPANSION_ASSESSMENT.md). No market measurements, forecasts or backtest results are fabricated here.

## 1. Numeric, identity and availability invariants

Reuse existing instrument/ISIN/exchange/currency identity and source/basis/calendar/finality provenance. Backend calculations use Decimal with explicit context/algorithm version; reuse34-digit calculation precision and 12-place derived serialization subject to reviewed per-method bounds. Seeds carry full precision; do not round recursive state every bar. JS number conversion is display geometry only, never canonical analytics. Prospective statistical solvers need a separate numeric-method approval, not an implicit float conversion of the existing price pipeline.

Only completed eligible bars enter default indicators. Daily final and intraday timeframes never mix; provisional/live/stream labels remain distinct. Known gaps/boundaries restart warm-up under the existing continuity policy; no imputed prices. Finite positive price/coherent OHLC and nonnegative exact integer volume validation precede every calculation. Missing prerequisites return structured unavailable reasons. Warm-up eligibility does not prove statistical stability or forecasting skill.

Supertrend state proposal: final upper equals basic upper when it is below previous final upper or Cprev exceeded previous final upper; otherwise retain previous upper. Final lower equals basic lower when it exceeds previous final lower or Cprev fell below previous final lower; otherwise retain previous lower. At first ATR, initialize final bands to basic bands and direction bullish if C>=midpoint, otherwise bearish. Thereafter bullish switches bearish only when C<current final lower; bearish switches bullish only when C>current final upper; equality retains direction. Plot selected lower/upper by direction. Publish this algorithm/version rather than claiming all Supertrend implementations are identical.

Historical validation for **every** proposed method: independent hand-worked Decimal golden fixtures with exact seeds/units; compare a separately written reference on eligible historical segments; record differences from third-party defaults; prove appending future bars cannot alter already computed eligible values; test all supported timeframes, missing/session gaps, splits/basis mismatch, very large/small finite inputs, limits, duplicate/revised bars and source revisions; provenance/input hash repeatability. Licensed real-history comparison supplements synthetic tests, not fabricated expected market results. Descriptive numerical agreement is not a profitable strategy backtest. Any strategy/performance claims require separately pre-registered rules/costs and chronological out-of-sample evidence.

## 3. Correlation and beta contract

For compatible positive prices, r_t=ln(P_t/Pprev) or explicit simple returns. Use one transform consistently; n daily returns require n+1 prices. Missing bars do not create a zero return; unequal multi-session spans cannot masquerade as one-session pairs. Yield and policy changes use basis points, not percent price returns. Monetary units, FX quote direction, calendars and prior publication eligibility are part of series identity.

Pearson = sum((x-xbar)*(y-ybar))/sqrt(sum((x-xbar)^2)*sum((y-ybar)^2)); zero variance unavailable. Spearman uses the same calculation on average ranks with explicit tie handling. Rolling beta of ETF on driver = sample covariance(ETF,driver)/sample variance(driver), units and intercept convention documented; driver variance0 unavailable. Same sample/centering in numerator and denominator.

Rolling windows20/60/120/252 refer to the selected NSE session grid. Report actual paired n, requested/effective dates, omitted pairs and a separately approved minimum sample policy; never silently extend windows to find enough data. Use Pearson/Spearman side by side where meaningful. Predefine candidate drivers/lags; control multiplicity/exploratory labeling. Serial dependence and overlapping windows invalidate naive IID certainty. Prefer moving-block bootstrap with stored integer resampling seed/block length; report uncertainty rather than a naked correlation.

Lag convention: corr(ETF return at session t, driver value/change known at t-k), k>0 means driver leads by k NSE sessions **after as-of alignment**. k<0 is retrospective exploration only, not predictive evidence. Store sign, units and availability convention. Regimes use contemporaneously knowable features or training-only fitted thresholds, not future returns; report per-regime counts and instability.

As-of alignment: require known publication/availability<=decision cutoff, independently of reference date. A US day's close generally occurs after the same date's NSE close; do not join purely on date. Keep UTC timestamps, source timezone/DST and exchange calendars. Carrying a latest-known policy/level is allowed only as a labelled stale state feature with age; do not manufacture daily releases or forward-fill returns. For monthly/quarterly series, use release changes/events or match analysis frequency; do not count repeated values as independent new evidence. Unknown publication time is ineligible for validated replay, even if today?s display can cite a dated source.

## 4. Exact currency/domestic/fund decomposition

Define positive compatible values at common cutoffs: G=USD bullion/unit, X=INR/USD, k=fixed physical/unit conversion, B=independent comparable domestic bullion benchmark, N=NAV/unit, P=ETF market price/unit. Let D=B/(k*G*X), F=N/B, M=P/N. Then exactly:

P_t/P_prev = (G_t/G_prev)*(X_t/X_prev)*(D_t/D_prev)*(F_t/F_prev)*(M_t/M_prev).

Simple returns require multiplicative interactions: (1+rG)*(1+rX)*(1+rD)*(1+rF)*(1+rM)-1, not a naive sum. For positive values, log returns add exactly. F contains fund expenses/tracking/unit effects under the chosen benchmark, not an isolated TER estimate; M captures NAV premium movement. Corporate actions/distributions/ETF unit conversions must be handled on a compatible declared basis.

Without independently observed B, split domestic duty/premium effects from residual is not identified. Report residual=ETF log return - bullion log return - FX log return, and only split NAV/premium when qualified N exists. Do not label residual as tax, fees or causation. Forecast scenarios vary stated components and retain interaction effects; approximations must be named. Raw TATAGOLD/TATSILV price division is not the gold/silver ratio.

## 5. Proposed typed data and module boundaries

Common SeriesIdentity: provider/dataset/metric, verified instrument or macro code, unit/currency, frequency/calendar, price/adjustment basis and source contract version. Common Evidence: source URL/reference/digest, license version and use grants; reference/valuation/event time; publisher time and precision/uncertainty; effective time; retrieved_at; vintage/revision/supersedes; finality/quality and source provenance. Unknown times remain unknown, not copied from retrieval time.

FundamentalFact adds scheme ISIN, metric enum, reported/derived distinction, typed Decimal/text/document value, valuation/effective period, original units and derivation references. MacroObservation adds series identity/reference period/first-release and revised vintages. EventRevision schema: event ID/type (scheduled or unscheduled), source/reference, publication/first-known/effective times, geography, affected instruments, reference period/units, expected value with provider and pre-release timestamp, actual first-release value, revised value/version, surprise and confidence/source quality. Missing expectation -> unavailable surprise; confidence is source/evidence quality, not an invented market-impact probability. Surprise=actual-first_release minus licensed pre-release expectation, with units; standardized surprise uses training-only historical surprise scale, not full-sample future information.

Event taxonomy: scheduled Fed/BOJ/ECB/RBI decisions, CPI/PCE and employment releases; Indian duty changes; central-bank gold purchases; commodity supply disruptions; major geopolitical news; ETF regulatory/structural changes; significant bullion supply/demand reports. Keep scheduled calendars distinct from unscheduled first-known events.

Event analyses: pre-event[-5,-1] and post-event[0,+1]/[+1,+5] NSE-session windows as proposals; exact release/after-hours mapping and benchmark defined first. Intraday30-minute effects require qualified intraday bars, not daily approximations. Estimate any expected-return benchmark only on pre-event data. Flag overlapping CPI/Fed/geopolitical releases and clustering; block/cluster uncertainty, sample counts and multiple comparisons. Scheduled releases use actual publication time, not just planned calendar time. Unscheduled headlines need first-known source evidence; corrections are append-only versions. Do not infer causality from a headline.

Logical interfaces: SourceAdapter -> typed observations/evidence; EligibilityService -> as-of eligible snapshot; Technical/Fundamental/Correlation/Event calculators -> immutable result with parameters/input hash/quality; FeatureBuilder -> versioned feature snapshot; Forecaster -> distribution/scenario; Evaluator -> held-out metrics/evidence. UI reads results, never fetches provider secrets or recomputes financial indicators. Events/AI text are untrusted external content and cannot initiate tools/trades or override execution boundaries.

Future PostgreSQL candidates (only after review/retention rights): qualified-series registry, fundamental facts, macro vintages, event revisions, feature snapshot manifests, forecast runs and evaluation manifests. Reuse current DataSource/catalog and migration conventions; do not force NAV/macro/news into canonical OHLCV or duplicate provider identities. Per-dataset permissions distinguish retrieval/storage/analysis/display/backups/redistribution/ML. No models/migrations/endpoints are implemented now. No scheduler/new microservice/trading/account layer.

## 6. Forecast and evaluation contracts

ForecastSpec: target instrument/basis, origin UTC/cutoff, last actually available price, horizon in NSE sessions (1/5/20/60/120/252), target availability/maturity, model/version/config/seed, source and feature manifest/vintages, estimation window, missing/stale policy and supported regimes. Dhan?s T-1 daily availability must be respected. A same-day provisional model, if ever proposed, is a separately labelled model rather than silently using final data. No total-return forecast from price-only data.

Phase1: deterministic evidence, historical conditional scenarios and event studies without fitted prediction claims. Phase2 baselines: no-change zero-return point forecast; expanding historical h-session return empirical distribution (dates/dependence/sample counts disclosed); simple volatility baseline. Then, if justified, training-only regularized regression/simple regime or volatility models. Phase3 ML only after separate rights/sample/numeric-method/evidence review. A point random-walk/no-change forecast alone is not a calibrated distribution. Unknown sample/uncertainty yields unavailable probabilities, not a default50%.

Distribution contract: expected/median return, quantiles/intervals, P(return>0), configurable threshold probabilities, downside quantile/expected shortfall only when tails are supported, volatility/scenario assumptions, data quality and uncertainty; supporting/contradicting features, model/source versions and all relevant validation results. Expected shortfall from sparse long-horizon samples should be unavailable rather than falsely precise. Contributions describe model behavior, not causal effects or guaranteed targets. Report evidence/signal strength, held-out historical reliability and data quality as separate dimensions, not an arbitrary composite probability.

Chronological outer train/validation/test, rolling/expanding walk-forward, nested tuning, immutable final holdout; fit imputation/scaling/rank/feature selection only on training. Purge training labels whose end overlaps validation/test origins; gap/embargo at least the relevant horizon/availability uncertainty where necessary. Evaluate only matured outcomes and state actual independent nonoverlapping windows. Include volatile/trending/flat regimes where evidence exists; do not manufacture regimes to conceal poor results. Current shorter ETF histories of roughly 250 observations cannot form252-session labels; the extended542-row TATSILV history still has only about two nonoverlapping252-session outcomes. Younger ETFs and unavailable vintage archives remain hard blockers, not solved by resampling.

Metrics: point MAE/RMSE and relative skill versus no-change/history on identical targets; directional ROC/PR discrimination separately from Brier/log-loss calibration and reliability bins; distributions CRPS or quantile pinball loss, prediction-interval coverage/width and tail sample counts. Use confidence intervals respecting serial/label overlap (block bootstrap), and disclose many-model/lag/horizon search. Review acceptance thresholds/sample sufficiency before experiments; model fit alone earns no predictive label.

Reproducibility manifests include code/dependency/model versions, all dataset/vintage references, parameters/seeds, forecast-origin availability checks, split/purge boundaries, metrics and omitted cases. Store point-in-time manifests/values only under retention/training grants. Later strategy tests require spread/fee/slippage/next-eligible execution and transaction-cost sensitivity; no execution capability is necessary. Monitor feature/target missingness, vintage/source drift, distribution/calibration drift and benchmark degradation; review triggers and retraining schedules are not authorized now.
