## Interfaces and state

Authenticated compute-only POST run/evaluate and GET context/list/tracking APIs under /api/v1/research/forecasts. Read a single repeatable-read canonical snapshot, compare all selected models on that snapshot, then run existing deterministic engines in the bounded worker thread. No SQL/file writes or provider calls inside forecast APIs. Manual data refresh calls the existing bounded acquisition route only on owner action.

Cap lookback1000, input5000, evaluation80 origins/period<=1100calendar days, models3, one compute request at a time, bounded request rate and cooperative30-second deadline/cancellation. Cache at most32 forecast runs in process RAM through target plus7days, capped at365days. Evaluation summaries are returned transiently, without a persistent or cached experiment ledger. No background worker, scheduler, GPU, localStorage or persistent forecast ledger. Restart/expiry loses tracking. Preserve immutable prediction/creation/cutoff/fingerprint; tracking reads later finalized observations and blocks changed input hashes instead of rewriting a forecast.

Dashboard adds Forecasting Research, retains Daily/Intraday/Technical views, uses existing charts and 15-row viewports. Point models show endpoints only, no interpolated path. B03 has volatility only. Historical results distinguish eligible/scored/pending/excluded cutoffs and conditional data limits, with price/return bias added to existing metrics. No trading controls, winner claim, probabilities or invented outcomes.

Tests must cover strict real-type policy, original synthetic guard, timestamps/first-seen filtering, calendar bounds/exceptions, missing/invalid data, all models, evaluator exclusion/bias/common samples, tracking maturity/revisions/expiry, resource/cancellation/security boundaries, UI states and native browser workflow.
