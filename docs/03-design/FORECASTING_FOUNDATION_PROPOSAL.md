# Forecasting foundation proposal - Package 2C

Date: 2026-11-06. **Proposed architecture/contracts/evaluation policy only. No forecasting engine, models, training dependencies, forecast endpoints or migrations implemented.** Authority: Package 2 design authorization. The [FRC extension](../04-planning/FORECASTING_REQUIREMENTS_EXTENSION.md) is Proposed throughout; REQ-BL-1.0 remains immutable. This refines the forecasting sections of [the earlier analytical proposal](RESEARCH_ANALYTICS_PROPOSAL.md); other proposed analytics remain unimplemented unless explicitly listed in the [Package 2 checkpoint](../04-planning/TECHNICAL_PACKAGE_2_CHECKPOINT.md).

## 1. Architecture and boundaries

Preserve ADR-01 modular monolith, ADR-02 React and ADR-06 deterministic canonical Decimal analytics. Logical modules are boundaries within the backend, not new deployable services. The UI consumes typed results; provider adapters and credentials stay outside models. No scheduler, portfolio/account access, order interface, ML runtime or external inference call is required for this proposal.

| Logical component | Responsibility / handoff | FRC |
| --- | --- | --- |
| Forecast Dataset Builder | Qualified canonical snapshot, basis/calendar/cutoff checks, immutable input manifest -> features | 003,015 |
| Feature Engineering | Versioned training-only transformations, units/masks/as-of alignment -> feature snapshot | 003,016 |
| Forecast Model Interface | Capability discovery, validate/fit/predict contracts with bounded resources and typed failures | 001,002,013 |
| Model Registry | Immutable model/config/artifact/dependency/data versions and lifecycle review | 004,014 |
| Baseline Models | Independently checked no-change/drift/volatility benchmarks on same inputs | 005 |
| Forecast Distribution | Validate supported points/quantiles/probabilities/volatility; separate hypothetical paths | 006,007 |
| Calibration and Evaluation | Fit calibration on eligible validation subset; untouched test scoring and uncertainty | 008,011 |
| Walk-Forward Backtesting | Chronological origins, training-only transformations, label purge/embargo/maturity | 009,015 |
| Forecast Evidence Ledger | Origin-time manifest/forecast, later attributable outcomes; retention gates before writes | 010 |
| Forecast Visualization | Actual/median/interval/scenario/evaluation views, exact accessible values and qualification | 012 |
| External Model Adapters | Optional isolated capability mapping, validation, timeout and artifact rights | 013,014 |
| Multi-Factor Forecast Reconciliation | Preserve independent model outputs/conflicts and evidence; no automatic ensemble probability | 011,016 |

Flow: existing qualified source snapshot -> Dataset Builder -> Feature Engineering -> model interface/baselines -> distribution validation -> origin evidence -> visualization. Walk-forward orchestrates this same path per cutoff; calibration never sees final holdout. Later realized outcomes join by original forecast ID/target grid, not by rewriting the prediction. Reconciliation is a separate proposed policy; models retain their own outputs and calibration. Correlated SMA/EMA/MACD evidence cannot be counted as three independent confirmations.

## 2. Proposed contracts (design, not executable schemas)

All prices/returns/probabilities serialized as named-unit decimal strings. Canonical OHLCV and existing technical calculations keep Decimal; statistical solvers/ML would need separately reviewed precision, conversion tolerances and reproducibility policy. A model output never becomes a canonical observation. Contracts carry schema_version and explicit unavailable/error reasons; no null-to-zero coercion.

**ForecastRequest**: request_id; instrument identity (catalog ID, ISIN, venue, currency); target=price-only simple return `C_target/C_origin-1`; explicit price basis/source version; timeframe initially 1d; horizons_session_count initially [1,5,20,60,120]; origin_session; decision_cutoff_utc; last_eligible_observation_time; lookback_sessions; dataset_manifest_id/digest; feature_manifest_id/digest; model_version/config_digest; seed; resource limits; purpose=PRIVATE_RESEARCH. Other targets, total return or intraday horizons need separate reviewed definitions.

**DatasetSnapshot**: snapshot_id/digest, source contract/evidence versions, instrument/basis/currency/unit, timeframe, exchange_timezone, calendar_id/version/session grid, requested/effective range; canonical observation ID/hash/batch references; observed/final/available timestamps and precision; retrieval time; revision/vintage; complete-bar flags; quality status and missing/duplicate/rejected-session counts; available-at-origin audit; rights_reference and separate retrieval/storage/analysis/display/backups/redistribution/training/derived-output grants. Unknown remains unknown. Replay requires actual historical availability evidence, not today's retrieval timestamp assigned to an old bar.

**FeatureSnapshot**: ordered name/version/type/unit/source/expression; reference time, first-known/publication time, vintage and available-at-origin flag; age/staleness limit; missing mask/reason; transform fit-range/hash; required/optional role; source permissions. No future realized feature values, future policy rates or revised macro releases in a historical forecast. Future calendar-only features are allowed only if their historical knowledge is established. Optional unavailable families are omitted/masked under a reviewed model policy, never silently zero-filled.

**ModelDescriptor/Capabilities**: model_id/version, code/dependency/config digests; training/validation/cutoff and universe; supported targets/bases/timeframes/horizons/context limits, required OHLCV/feature fields; output capabilities (point_path, mean_return, median_return, quantiles, probabilities, volatility, individual_scenarios); calibration support/status; runtime/device/numeric/seed determinism; optional weights/tokenizer digests and licenses; training-use permissions; lifecycle and reviewer evidence. Proposed lifecycle: PROPOSED -> RESEARCH_ONLY -> VALIDATED_FOR_NAMED_SCOPE; DISABLED/RETIRED as separate terminal/review transitions. Promotion is explicit, not achieved by passing interface tests.

**ForecastResult**: forecast_id, original request/config/model versions, created_at_utc, cutoff, manifest fingerprints, instrument/basis/unit, target definition and per-horizon target_session/matures_at/status; optional expected_return, median_return, quantiles[{level,value}], probabilities[{event,threshold,value}], volatility with estimator/period/unit; output capability and unavailable reason per field; calibration_method/version/fit-range/evidence_id/status; source quality/evidence support/forecast reliability as separate fields; numerical policy; warnings/runtime cost. Values must be finite, probabilities within [0,1], quantile levels ordered with nondecreasing values and compatible units. Unsupported outputs use null + UNSUPPORTED; insufficient evidence uses INSUFFICIENT_HISTORY/UNASSESSED, not a guessed distribution.

**ScenarioBundle**: classification=SIMULATED, separate ID/model/seed/sampling params/path count, future verified session grid, optional individually exposed price paths; assumptions and empirical/calibration limitations. Never store in price_observations, never pass off simulated volume/OHLC as observed. A mean path cannot be expanded into individual paths or quantiles. Reject nonfinite/nonpositive price paths or inconsistent OHLC; do not silently repair outputs.

**EvaluationResult/EvidenceManifest**: immutable original forecast/request/manifests and creation time; experiment/split/transform/model/calibration versions; target horizon/grid and realized price basis/observation/vintage/available_at; outcome status PENDING/MATURED/UNAVAILABLE/REVISED; target value with unit; metric definitions/values/support/exclusions and paired benchmark; uncertainty/resampling seed; runtime hardware/limits; review disposition. Corrections append attributable revisions; old forecast and vintage remain identifiable. Retain values/artifacts only under explicit dataset/output storage and backup grants; a hash alone does not automatically settle contractual retention rights. Proposed evidence remains transient until permissions are established; no ledger table is created here.

## 3. Baseline definitions and numeric review

Proposed baseline contracts, not implemented:

- **No-change**: future price point equals last eligible completed close, return=0 for every supported horizon. This is a point forecast, not a 50% direction forecast or a zero-width calibrated interval.
- **Historical drift**: training-only one-session simple returns r_i=C_i/C_(i-1)-1, mean mu; price point C_origin*(1+mu)^h, h-session return (1+mu)^h-1. Reject unavailable/nonfinite inputs; keep model choice explicit rather than conflating mean simple and mean log drift. This formula imposes a constant-drift assumption, not proof of expected future return.
- **Historical volatility**: training-only sample standard deviation of one-session returns (n-1 denominator), explicit estimation window. sqrt(h)*sigma is a separately labeled IID scaling assumption; empirical overlapping h-session volatility is a different named estimator. A volatility estimate alone supplies neither a full distribution nor calibrated tails.
- **Empirical historical returns**, if later approved: training-only matched h-session returns with actual dependence/support counts, no forward-fill. Quantiles/positive/downside frequencies require a versioned quantile convention and support/calibration evidence. Overlapping samples are not independent evidence.

Use independent rational/Decimal hand vectors where possible. Root/power/statistical routines require explicit precision/error budgets; prospective NumPy/PyTorch conversion is outside canonical analytics and needs approval. Seeds/repeatability do not guarantee identical GPU kernels or statistical validity.

## 4. Evaluation and eligibility specification - all thresholds Proposed

Target initially price-only simple return at the h-th verified NSE session after the last eligible origin close. Price-point metrics must use the same basis and reference price; no total-return or NAV claim. A decision cutoff can occur after a session close while Dhan daily bars remain unavailable until T-1; origin price/session and actual decision cutoff must both be recorded. Never silently label a stale available close as today's close. Target sessions must remain in the future at the decision cutoff; otherwise the request is unavailable rather than silently shifting its origin. Outcomes mature only after target session completes AND eligible publication/availability evidence is available.

**Proposed technical floors for review, not predictive acceptance thresholds:** last-value calculation needs one qualified completed close; drift/volatility benchmarking requires >=253 consecutive eligible closes (252 one-session returns). Model training initially >=max(252,context lookback) sessions, separate validation >=max(60,2*h) sessions, untouched evaluation >=max(252,20*h) sessions with >=20 nonoverlapping matured outcomes per reported horizon. Calibrated probability claims require >=100 independent matured outcomes, with proposed five reliability bins requiring >=20 outcomes/bin plus positive and negative outcome support; sparse bins are suppressed. These intentionally conservative floors may block 60/120-session evaluation for years. They are not claims of sufficient statistical power, profitability or domain suitability; owner must review support, class balance, interval uncertainty and costs before adoption.

Coverage is evaluated over each required context/label/session grid: zero unresolved duplicates, mixed bases, invalid OHLCV, future-available features or incomplete bars; 100% of required sessions/features eligible in the actual model context and label window. An unavailable target/origin is excluded with a reason and count, never converted to zero. A known gap may start a new eligible segment; do not bridge it or quietly extend requested windows to meet counts. Optional masked features require an explicit trained policy; no retroactive imputation fit on all data. Calendar uncertainty, adjustment changes and current-source vintage insufficiency block validated replay even if a technical indicator can be displayed.

**Chronological protocol:** freeze universe/targets/lookbacks/metrics/search budget and holdout first. Use expanding/rolling outer origins; nested temporal validation for hyperparameters and calibration; fit scaling/imputation/features/regime thresholds only on training. Purge training labels that end in validation/test origin ranges; embargo overlap by at least h sessions and any further availability uncertainty under the chosen split rule. Log exact boundaries rather than relying on a generic gap. Same eligible origins for candidate and benchmark; disclose omitted/failed forecasts. Freeze final holdout until model selection is complete. Keep historical development, walk-forward/OOS and forward paper evidence distinct (REQ-06-018); no paper trading is implemented.

| Metric | Proposed definition / required disclosure |
| --- | --- |
| MAE | mean(abs(predicted return - realized return)); same h, target, basis, units and origins |
| RMSE | sqrt(mean(error^2)); disclose tail sensitivity and numeric policy |
| Directional hit rate | exact sign agreement; zero predicted/realized return is its own class; disclose zeros and confusion counts rather than count zero as an up bet |
| Volatility forecast error | compare predicted h-window volatility with realized sqrt(sum(one-session return^2)) as an explicitly named realized-volatility proxy; same horizon/units, not a directly observed latent variance; report MAE/RMSE and sample support |
| Interval coverage | fraction of matured outcomes in each stated central interval, its nominal level/width and binomial/dependence-aware uncertainty; coverage alone can reward useless wide bands |
| CRPS | when a distribution or actual samples are supported: E(abs(X-y))-0.5*E(abs(X-Xprime)); use an independent sample estimator or validated distribution routine; do not derive from a mean path |
| Calibration error | reliability bins/counts/confidence ranges for P(return>0) and downside events; predeclared expected calibration error plus Brier score/log loss where support exists; proper scores and calibration/discrimination reported separately |
| Benchmark-relative | paired loss difference and skill=1-loss_model/loss_baseline when baseline loss>0; otherwise unavailable ratio. Same targets/origins, confidence bounds and runtime/memory cost |

For quantile-only models use pinball loss with disclosed quantile levels; do not claim full CRPS from sparse quantiles without a justified approximation. Log loss needs a disclosed numeric clipping rule with unclipped probability diagnostics. Use moving/block resampling or nonoverlapping outcome subsets to respect temporal dependence and overlapping labels; record block policy/seed/replicates. Report horizon/instrument and pre-origin-defined regime strata with sample support, plus multiple-model/search effects. Numerical agreement, fit, directional hits or a favorable chart alone do not establish predictive value. Business skill tolerances remain open under REQ-06-006; no fabricated pass threshold is introduced.

**Reproducibility:** code/environment/lockfile/data/calendar/feature/vintage/model/config/seed/split/metric versions, availability audit, rejected cases and runtime hardware accompany each run. Repeat deterministic baselines exactly; later stochastic solvers declare tolerances and repeatability limits. Retrospectively revised prices invalidate the old experiment only through a new attributable experiment; never rewrite its origin evidence.

## 5. Kronos source assessment - external review only

Reviewed official upstream files on 2026-11-06, not a pinned dependency: [README](https://github.com/shiyu-coder/Kronos/blob/master/README.md), [model/kronos.py](https://github.com/shiyu-coder/Kronos/blob/master/model/kronos.py), [CSV fine-tuning guide](https://github.com/shiyu-coder/Kronos/blob/master/finetune_csv/README.md), [CSV trainer](https://github.com/shiyu-coder/Kronos/blob/master/finetune_csv/finetune_base_model.py), [MIT source license](https://github.com/shiyu-coder/Kronos/blob/master/LICENSE). These moving branch URLs are review evidence, not a reproducible approved model version; any future adapter must pin source/checkpoint/tokenizer digests. No upstream code, tokenizer, weights, PyTorch or training package was copied or installed.

Confirmed in the predictor source: OHLC plus volume/amount inputs, calendar features, context normalization/clipping, bounded context/horizon and sampling parameters. Crucially, the autoregressive helper averages samples before returning the public prediction path; the wrapper does not expose individual paths or a calibrated distribution. It can fill missing volume with zero and derive amount from volume and average OHLC. We will not treat these substitutions as observed data. A future adapter must reject unsupported/missing required inputs or label transformations under a reviewed policy. A returned averaged path alone supports neither median, quantiles, probabilities nor retained scenarios. Context length and synthetic sample count do not establish historical support or calibration.

The CSV training helper uses chronological partitions but includes forward-fill and normalization across its lookback-plus-target window; predictor inference normalizes context only. This difference warrants independent review before any training/evaluation design is adopted. It is not evidence that our proposed point-in-time pipeline is implemented, nor a blanket conclusion about external model validity. Never copy preprocessing assumptions into canonical observations or held-out evaluation.

Reusable concepts are model-neutral: explicit context/horizon, calendar-aware future grid, reproducible sampling configuration, independent tokenizer/model artifact identity and batch shape validation. Proposed contracts above generalize these concepts while exposing capability gaps. MIT source licensing does not by itself establish checkpoint, training-data, broker-data training or derived-output retention rights. Indian ETF suitability, adjusted-price compatibility, timestamp semantics, calibration, compute budget and numeric isolation remain unqualified. Recommendation: no Kronos integration in this package; evaluate later only against approved baselines and an untouched qualified holdout.

## 6. Multi-factor extension and source governance

Future features can include USD/INR, DXY, US real yields, Fed/BOJ policy, inflation releases, physical-unit gold/silver ratio, global supply/demand, ETF flows, NAV/tracking differences and economic/geopolitical events. None is fetched or implemented here. Reuse the source-specific assessment in [research expansion assessment](../04-planning/RESEARCH_EXPANSION_ASSESSMENT.md); rights must separately cover API retrieval, local retention/backups, personal analysis/display, derived outputs, redistribution and training where relevant. Public access is not a grant.

FX quote direction/unit, bullion weight unit, yield basis points versus returns, market-price versus NAV valuation, observation frequency and stale-state semantics belong to feature identity. Raw ETF-share price ratios are not physical gold/silver ratios. Correlation is a descriptive feature, not causal attribution. Optional feature groups require feature masks, source evidence and their own review; a model cannot demand credentials or fetch missing data itself.

As-of joining uses publisher/first-known time with source timezone/DST and vintage, never reference date alone. A US close or release after NSE close belongs only to a later eligible decision cutoff. Historical Fed/BOJ announcements need actual publication timestamps; macro revisions retain first-release vintages. Unknown time or absent vintage means ineligible for validated replay. Latest-known low-frequency levels may be labeled stale state features with age; repeated levels are not independent releases or forward-filled returns. Source/retention qualification and calendar updates must precede model feature activation.
